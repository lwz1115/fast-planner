# 错误处理文档

本文档描述 FastAPI-Fast-Planner 接口的错误处理实现。

## 概述

错误处理系统为所有故障场景提供全面、结构化的错误响应。它将 Python 异常映射到适当的 HTTP 状态代码，并向客户端返回一致的错误信息。

## 架构

错误处理系统由三个主要组件组成：

1. **自定义异常类**（`exceptions.py`）：为不同错误场景定义特定的异常类型
2. **异常处理器**（`error_handlers.py`）：将异常转换为具有适当状态代码的 HTTP 响应
3. **错误响应模型**（`models.py`）：标准化的错误信息结构

## 错误类别

### 1. 验证错误（400 Bad Request）

**状态代码：** 400

**使用场景：** 请求参数无效、超出范围或未通过验证检查

**异常类：**
- `ValidationException`：验证错误的基类
- `PositionOutOfBoundsException`：起点或目标位置超出地图边界
- `InvalidAlgorithmException`：指定了不支持的算法

**示例响应：**
```json
{
  "code": "start_out_of_bounds",
  "message": "起点位置超出地图边界",
  "details": "地图边界：X=[0, 40], Y=[0, 20], Z=[0, 5]"
}
```

### 2. 规划失败（422 Unprocessable Entity）

**状态代码：** 422

**使用场景：** Fast-Planner 无法完成规划请求

**异常类：**
- `PlanningFailureException`：规划失败的基类
- `NoPathFoundException`：未找到无碰撞路径到目标
- `GoalInCollisionException`：目标位置与障碍物碰撞
- `StartInCollisionException`：起点位置与障碍物碰撞

**示例响应：**
```json
{
  "code": "no_path_found",
  "message": "Fast-Planner 无法找到到目标的无碰撞路径",
  "details": "目标位置可能无法到达或被障碍物包围"
}
```

### 3. 服务不可用（503 Service Unavailable）

**状态代码：** 503

**使用场景：** 所需服务或数据不可用

**异常类：**
- `ServiceUnavailableException`：服务不可用的基类
- `OdometryUnavailableException`：里程计数据不可用或过旧
- `ROSConnectionException`：ROS 连接丢失或不可用

**示例响应：**
```json
{
  "code": "odometry_unavailable",
  "message": "没有可用的最新里程计数据",
  "details": "里程计数据未发布或过旧（>1 秒）"
}
```

### 4. 超时错误（504 Gateway Timeout）

**状态代码：** 504

**使用场景：** 操作超过配置的超时时间

**异常类：**
- `TimeoutException`：超时错误的基类
- `PlanningTimeoutException`：规划操作超时

**示例响应：**
```json
{
  "code": "planning_timeout",
  "message": "规划在 5.0 秒后超时",
  "details": "Fast-Planner 未在超时时间内返回轨迹。目标可能无法到达或规划器过载。"
}
```

## 错误响应格式

所有错误响应遵循 `ErrorInfo` 模型结构：

```python
{
  "code": str,      # 机器可读的错误代码
  "message": str,   # 人类可读的错误消息
  "details": str    # 附加错误上下文（可选）
}
```

## 日志记录

所有错误都以适当的严重级别记录：

- **WARNING**：预期错误（验证、规划失败、超时）
- **ERROR**：意外错误、服务不可用、内部错误

日志条目包括：
- 错误代码
- 错误消息
- 请求路径
- 附加上下文（详情、意外错误的堆栈跟踪）

示例日志条目：
```
2025-11-11 10:30:15,123 - fastapi_planner.error_handlers - WARNING - 规划失败：no_path_found - Fast-Planner 无法找到到目标的无碰撞路径
```

## 使用示例

### 在代码中引发异常

```python
from fastapi_planner.exceptions import (
    NoPathFoundException,
    PositionOutOfBoundsException,
    PlanningTimeoutException
)

# 引发特定异常
if not path_found:
    raise NoPathFoundException(
        details="目标可能被障碍物包围"
    )

# 使用自定义详情引发
if position_out_of_bounds:
    raise PositionOutOfBoundsException(
        position_type="goal",
        bounds_info="X=[0, 40], Y=[0, 20], Z=[0, 5]"
    )

# 引发超时异常
if timeout_occurred:
    raise PlanningTimeoutException(
        timeout_seconds=5.0,
        details="规划器可能过载"
    )
```

### 在客户端代码中处理错误

```python
import requests

response = requests.post(
    "http://localhost:8000/plan",
    json={
        "start": {"x": 0, "y": 0, "z": 1},
        "goal": {"x": 100, "y": 0, "z": 1}  # 超出边界
    }
)

if response.status_code == 400:
    error = response.json()
    print(f"验证错误：{error['message']}")
    print(f"详情：{error['details']}")
elif response.status_code == 422:
    error = response.json()
    print(f"规划失败：{error['message']}")
elif response.status_code == 503:
    error = response.json()
    print(f"服务不可用：{error['message']}")
elif response.status_code == 504:
    error = response.json()
    print(f"超时：{error['message']}")
```

## 异常处理器注册

异常处理器在应用启动时自动注册：

```python
from fastapi_planner.error_handlers import register_exception_handlers

app = FastAPI()
register_exception_handlers(app)
```

这会为以下内容注册处理器：
- 自定义异常类（ValidationException、PlanningFailureException 等）
- 标准 Python 异常（ValueError、Exception）
- Pydantic 验证错误（RequestValidationError、ValidationError）

## 需求覆盖

此实现满足以下需求：

- **3.1**：未找到路径错误返回 422，错误代码为 "no_path_found"
- **3.2**：目标碰撞错误返回 422，错误代码为 "goal_in_collision"
- **3.3**：起点碰撞错误返回 422，错误代码为 "start_in_collision"
- **3.4**：超时错误返回 504，错误代码为 "planning_timeout"
- **3.5**：所有错误响应包含描述性消息和详情

## 最佳实践

1. **使用特定异常**：优先使用特定异常类（如 `NoPathFoundException`）而不是通用异常
2. **包含详情**：始终在异常消息中提供有用的详情
3. **引发前记录**：在引发异常前记录错误上下文以便调试
4. **不要捕获并重新引发**：让异常处理器将异常转换为响应
5. **测试错误路径**：确保错误场景被测试覆盖

## 未来增强

错误处理系统的潜在改进：

1. **错误代码枚举**：将错误代码定义为常量以防止拼写错误
2. **本地化**：支持错误消息的多种语言
3. **错误指标**：跟踪错误率和类型以进行监控
4. **重试提示**：为瞬态错误包含 retry-after 头
5. **错误文档**：从异常类自动生成错误代码文档
