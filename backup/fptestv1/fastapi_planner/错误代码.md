# 错误代码快速参考

本文档提供 FastAPI-Fast-Planner 接口返回的所有错误代码的快速参考。

## 错误代码格式

所有错误响应遵循此结构：
```json
{
  "code": "error_code",
  "message": "人类可读的消息",
  "details": "附加上下文（可选）"
}
```

## 验证错误（400）

| 代码 | 消息 | 发生时机 |
|------|------|----------|
| `validation_error` | 无效的请求参数 | 请求体未通过 Pydantic 验证 |
| `value_error` | 请求中的值无效 | 值通过验证但未通过业务逻辑 |
| `start_out_of_bounds` | 起点位置超出地图边界 | 起点位置超过配置的地图限制 |
| `goal_out_of_bounds` | 目标位置超出地图边界 | 目标位置超过配置的地图限制 |
| `invalid_algorithm` | 不支持的算法：{name} | 算法参数不是 "kinodynamic" 或 "topological" |

## 规划失败（422）

| 代码 | 消息 | 发生时机 |
|------|------|----------|
| `no_path_found` | Fast-Planner 无法找到到目标的无碰撞路径 | 不存在到达目标的有效轨迹 |
| `goal_in_collision` | 目标位置与障碍物碰撞 | 目标位置与障碍物重叠 |
| `start_in_collision` | 起点位置与障碍物碰撞 | 起点位置与障碍物重叠 |
| `trajectory_conversion_error` | 无法将 B 样条轨迹转换为航点 | B 样条评估期间出错 |
| `trajectory_validation_error` | 生成的轨迹未通过验证 | 轨迹不满足要求 |
| `no_trajectory_received` | 未从 Fast-Planner 收到轨迹 | Fast-Planner 未响应轨迹 |

## 服务不可用（503）

| 代码 | 消息 | 发生时机 |
|------|------|----------|
| `service_not_initialized` | 规划服务未初始化 | 服务仍在启动中 |
| `ros_disconnected` | ROS 连接不可用 | ROS Master 无法访问 |
| `odometry_unavailable` | 没有可用的最新里程计数据 | 里程计话题未发布或数据过旧 |
| `ros_communication_error` | 无法向 Fast-Planner 发布目标 | 无法向 ROS 发送消息 |

## 超时错误（504）

| 代码 | 消息 | 发生时机 |
|------|------|----------|
| `planning_timeout` | 规划在 {N} 秒后超时 | Fast-Planner 未在超时时间内响应 |

## 内部错误（500）

| 代码 | 消息 | 发生时机 |
|------|------|----------|
| `internal_error` | 发生意外错误 | 服务代码中的未处理异常 |

## 使用示例

### 处理特定错误代码

```python
import requests

response = requests.post("http://localhost:8000/plan", json={...})

if response.status_code != 200:
    error = response.json()
    code = error["code"]
    
    if code == "no_path_found":
        print("无法到达目标 - 尝试不同的位置")
    elif code == "planning_timeout":
        print("规划耗时过长 - 尝试更近的目标")
    elif code == "start_out_of_bounds":
        print("起点位置在地图外")
    elif code == "odometry_unavailable":
        print("等待里程计数据...")
    else:
        print(f"错误：{error['message']}")
```

### 基于错误类型的重试逻辑

```python
def should_retry(error_code: str) -> bool:
    """根据错误代码确定是否应重试请求。"""
    
    # 重试瞬态错误
    transient_errors = [
        "odometry_unavailable",
        "ros_communication_error",
        "service_not_initialized"
    ]
    
    # 不重试永久性失败
    permanent_errors = [
        "start_out_of_bounds",
        "goal_out_of_bounds",
        "invalid_algorithm",
        "goal_in_collision",
        "start_in_collision"
    ]
    
    if error_code in transient_errors:
        return True
    elif error_code in permanent_errors:
        return False
    else:
        # 谨慎重试其他错误
        return True
```

## 常见场景

### 场景 1：位置超出边界

**请求：**
```json
{
  "start": {"x": 0, "y": 0, "z": 1},
  "goal": {"x": 100, "y": 0, "z": 1}
}
```

**响应（400）：**
```json
{
  "code": "goal_out_of_bounds",
  "message": "目标位置超出地图边界",
  "details": "地图边界：X=[0, 40], Y=[0, 20], Z=[0, 5]"
}
```

**解决方案：** 调整目标位置使其在地图边界内。

### 场景 2：未找到路径

**请求：**
```json
{
  "start": {"x": 0, "y": 0, "z": 1},
  "goal": {"x": 20, "y": 10, "z": 1}
}
```

**响应（422）：**
```json
{
  "code": "no_path_found",
  "message": "Fast-Planner 无法找到到目标的无碰撞路径",
  "details": "目标位置可能无法到达或被障碍物包围"
}
```

**解决方案：** 尝试不同的目标位置或检查阻挡路径的障碍物。

### 场景 3：规划超时

**请求：**
```json
{
  "start": {"x": 0, "y": 0, "z": 1},
  "goal": {"x": 30, "y": 15, "z": 3}
}
```

**响应（504）：**
```json
{
  "code": "planning_timeout",
  "message": "规划在 5.0 秒后超时",
  "details": "Fast-Planner 未在超时时间内返回轨迹。目标可能无法到达或规划器过载。"
}
```

**解决方案：** 尝试更近的目标，增加配置中的超时时间，或检查规划器是否过载。

### 场景 4：里程计不可用

**请求：**
```json
{
  "start": {"x": 0, "y": 0, "z": 1},
  "goal": {"x": 10, "y": 5, "z": 1},
  "use_current_odom": true
}
```

**响应（503）：**
```json
{
  "code": "odometry_unavailable",
  "message": "没有可用的最新里程计数据",
  "details": "无法使用当前里程计作为起点位置"
}
```

**解决方案：** 等待里程计数据发布或不使用 `use_current_odom` 标志。

## 最佳实践

1. **首先检查状态代码**：使用 HTTP 状态代码确定错误类别
2. **使用错误代码进行逻辑处理**：使用 `code` 字段进行程序化错误处理
3. **向用户显示消息**：向最终用户显示 `message` 字段
4. **记录详情**：记录 `details` 字段以便调试
5. **实现重试逻辑**：重试瞬态错误（503）但不重试永久性失败（400、422）
6. **监控错误率**：跟踪错误代码以识别系统问题
