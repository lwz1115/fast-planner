# FastPlanner 完整代码结构文档

## 项目概述

FastPlanner 是一个混合 ROS/FastAPI 项目，结合了 Fast-Planner（四旋翼轨迹规划系统）和 REST API 接口。项目由两个主要部分组成：

1. **Fast-Planner ROS 包** - C++ ROS Noetic/Melodic 无人机轨迹规划系统
2. **FastAPI 服务** - Python REST API 桥接层，通过 HTTP 暴露 Fast-Planner 功能

## 二、Fast-Planner ROS 包结构

### 2.1 核心规划模块 (`src/Fast-Planner/fast_planner/`)

#### **2.1.1 plan_manage - 规划管理器**
**功能**: 高层规划有限状态机（FSM），协调所有规划模块

**核心文件**:
- `kino_replan_fsm.h/cpp` - 动力学重规划状态机
  - 管理动力学规划的状态转换（INIT, WAIT_TARGET, GEN_NEW_TRAJ, REPLAN_TRAJ, EXEC_TRAJ）
  - 处理目标点接收、轨迹生成、重规划触发
  - 发布轨迹命令到控制器

- `topo_replan_fsm.h/cpp` - 拓扑重规划状态机
  - 管理拓扑规划的状态流程
  - 处理多条拓扑路径的选择和优化
  - 支持更复杂环境的路径规划

- `planner_manager.h/cpp` - 规划器管理器
  - 统一管理路径搜索、轨迹优化模块
  - 提供规划接口：kinodynamicReplan(), topoReplan()
  - 配置规划参数（速度、加速度限制等）

- `fast_planner_node.cpp` - ROS 节点主程序
  - 初始化 ROS 节点和所有模块
  - 启动 FSM 状态机
  - 处理 ROS 消息通信

- `traj_server.cpp` - 轨迹服务器
  - 发布轨迹跟踪命令
  - 管理轨迹执行状态

**Launch 文件**:
- `kino_replan.launch` - 启动动力学规划
- `topo_replan.launch` - 启动拓扑规划
- `kino_algorithm.xml` - 动力学算法参数配置
- `topo_algorithm.xml` - 拓扑算法参数配置
- `rviz.launch` - 启动 Rviz 可视化

#### **2.1.2 path_searching - 路径搜索**
**功能**: 前端路径搜索算法

**核心文件**:
- `kinodynamic_astar.h/cpp` - 动力学 A* 算法
  - 考虑动力学约束的 A* 搜索
  - 生成满足速度、加速度限制的初始路径
  - 使用状态空间搜索（位置 + 速度）

- `astar.h/cpp` - 标准 A* 算法
  - 几何 A* 路径搜索
  - 用于快速路径查找

- `topo_prm.h/cpp` - 拓扑 PRM（概率路线图）
  - 采样多条拓扑不同的路径
  - 构建路线图并搜索多条候选路径
  - 支持复杂环境的多路径规划

**算法特点**:
- Kinodynamic A*: 适合快速、激进飞行
- Topological PRM: 适合复杂环境，避免局部最优

#### **2.1.3 bspline - B 样条轨迹表示**
**功能**: B 样条曲线轨迹表示和操作

**核心文件**:
- `non_uniform_bspline.h/cpp` - 非均匀 B 样条
  - B 样条轨迹的数学表示
  - 轨迹评估：位置、速度、加速度、加加速度
  - 控制点操作和轨迹修改
  - 轨迹参数化和重参数化

**功能接口**:
- `getPos(t)` - 获取 t 时刻位置
- `getVel(t)` - 获取 t 时刻速度
- `getAcc(t)` - 获取 t 时刻加速度
- `getJerk(t)` - 获取 t 时刻加加速度
- `setControlPoint()` - 设置控制点
- `getTimeSpan()` - 获取时间跨度

---

#### **2.1.4 bspline_opt - B 样条优化**
**功能**: 基于梯度的 B 样条轨迹优化

**核心文件**:
- `bspline_optimizer.h/cpp` - B 样条优化器
  - 梯度下降优化轨迹
  - 优化目标：平滑性、安全性、动力学可行性
  - 代价函数：
    - 平滑代价（最小化加加速度）
    - 碰撞代价（ESDF 距离场）
    - 动力学可行性代价（速度、加速度限制）
    - 终点约束代价

**优化方法**:
- 使用 NLopt 库进行非线性优化
- L-BFGS 算法求解
- 支持多种约束条件

## 三、FastAPI 服务结构 (`fastapi_planner/`)

### 3.1 核心模块

#### **3.1.1 main.py - FastAPI 应用主程序**
**功能**: REST API 服务器

**API 端点**:

**健康检查**:
- `GET /` - 根路径，返回服务信息
- `GET /health` - 健康检查，返回服务状态
- `GET /health/detailed` - 详细健康检查（ROS 连接、话题状态）

**规划端点**:
- `POST /plan` - 执行轨迹规划
  - 输入：起点、终点、算法类型、速度/加速度限制
  - 输出：规划轨迹、执行时间、状态

- `POST /plan/kinodynamic` - 动力学规划
  - 使用 kinodynamic A* + B-spline 优化

- `POST /plan/topological` - 拓扑规划
  - 使用拓扑 PRM + 路径引导优化

**深度处理端点**:
- `POST /depth/process` - 处理深度图像
  - 输入：深度图像（base64）、相机参数
  - 输出：点云数据

- `POST /depth/publish` - 发布深度点云到 ROS
  - 将点云发布到 `/depth_cloud` 话题

**状态查询**:
- `GET /status/odometry` - 获取当前里程计
- `GET /status/trajectory` - 获取当前轨迹
- `GET /ros/topics` - 列出 ROS 话题

**特性**:
- 异步处理
- 错误处理和日志记录
- CORS 支持
- 请求验证（Pydantic）
- 超时控制

## 四、数据流和通信架构

### 4.1 ROS 话题通信

```
传感器数据流:
深度相机 → /pcl_render_node/depth → plan_env (SDF 地图)
点云 → /pcl_render_node/cloud → plan_env (ESDF)
里程计 → /state_ukf/odom → plan_manage (FSM)

规划数据流:
用户/API → /move_base_simple/goal → plan_manage (FSM)
plan_manage → path_searching (路径搜索)
path_searching → bspline_opt (轨迹优化)
bspline_opt → /planning/bspline → 控制器
plan_manage → /planning/pos_cmd → 控制器

可视化数据流:
plan_manage → traj_utils → Rviz (可视化标记)
plan_env → Rviz (地图可视化)
```

### 4.2 FastAPI 到 ROS 桥接

```
HTTP 请求流:
客户端 → FastAPI (main.py)
FastAPI → ros_bridge (发布目标)
ros_bridge → /move_base_simple/goal
Fast-Planner → 规划执行
Fast-Planner → /planning/bspline
ros_bridge → 订阅轨迹
ros_bridge → FastAPI
FastAPI → 客户端 (JSON 响应)
```

### 4.3 深度处理流

```
深度图像流:
客户端 → POST /depth/process (base64 图像)
depth_processor → 解码图像
depth_processor → 深度到点云转换
depth_processor → 坐标变换
depth_processor → 点云滤波
ros_bridge → 发布到 /depth_cloud
plan_env → 订阅点云
plan_env → 更新 ESDF 地图
```

## 五、关键算法和数据结构

### 5.1 动力学规划算法

**Kinodynamic A***:
1. 状态空间：(x, y, z, vx, vy, vz)
2. 动作空间：加速度采样
3. 代价函数：时间 + 启发式距离
4. 约束：速度限制、加速度限制

**B-spline 优化**:
1. 控制点参数化
2. 梯度下降优化
3. 代价函数：
   - 平滑性：∫||jerk||² dt
   - 碰撞：ESDF 距离惩罚
   - 动力学：速度/加速度惩罚
   - 终点：终点偏差惩罚

### 5.2 拓扑规划算法

**Topological PRM**:
1. 采样可见性图节点
2. 构建路线图
3. 搜索多条拓扑不同路径
4. 路径引导优化

**路径选择**:
- 评估每条路径的代价
- 选择最优路径
- 避免局部最优

### 5.3 ESDF 地图

**数据结构**:
- 3D 栅格地图（Voxel Grid）
- 每个栅格存储：
  - 占据状态（free/occupied）
  - 距离值（到最近障碍物）
  - 梯度向量（距离场梯度）

**更新算法**:
1. 深度图像/点云输入
2. 光线投射更新占据栅格
3. EDT 计算距离场
4. 计算梯度场

## 十、常见问题和调试

### 10.1 ROS 编译问题

**NLopt 版本问题**:
- 确保安装 NLopt v2.7.1（不是 v2.7.0 或 v2.8+）
- 检查：`pkg-config --modversion nlopt`

**Eigen3 问题**:
- 检查 Eigen3 版本兼容性
- 确保 CMake 能找到 Eigen3

**环境问题**:
- 确保加载 ROS 环境：`source /opt/ros/noetic/setup.bash`
- 检查 ROS_PACKAGE_PATH

### 10.2 FastAPI 服务问题

**ROS 连接问题**:
- 检查 ROS_MASTER_URI 设置
- 确认 roscore 正在运行
- 验证话题存在：`rostopic list`

**话题订阅问题**:
- 检查话题名称配置
- 确认 Fast-Planner 节点运行
- 查看日志：`fastapi_planner/` 目录

### 10.3 规划失败

**常见原因**:
- 里程计未发布
- 目标点超出地图边界
- 目标点在障碍物内
- 速度/加速度限制过严

**调试方法**:
1. 检查 Rviz 可视化
2. 查看地图边界配置
3. 调整 max_vel/max_acc 参数
4. 检查 ROS 日志

## 十四、坐标系统

### 14.1 坐标系定义

- **World Frame**: 固定全局坐标系（ENU：东-北-上）
- **Body Frame**: 无人机机体坐标系（前-左-上）
- **Camera Frame**: 深度相机坐标系（右-下-前）

### 14.2 坐标变换

- World → Body: 通过里程计位姿
- Camera → World: 通过相机位姿
- 深度图像 → 点云: 使用相机内参

### 14.3 默认相机内参

```
fx = 387.23  # 焦距 X
fy = 387.23  # 焦距 Y
cx = 321.05  # 主点 X
cy = 243.45  # 主点 Y
```
