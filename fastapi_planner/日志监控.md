# 日志和监控

本文档描述 FastAPI-Fast-Planner 接口的日志和监控功能。

## 概述

服务实现全面的日志和监控以支持：
- **请求/响应跟踪**：每个请求都记录时间信息
- **性能监控**：跟踪规划时间和成功率
- **错误跟踪**：所有错误都记录堆栈跟踪
- **结构化日志**：具有请求关联的一致日志格式

## 日志配置

### 日志级别

服务支持标准 Python 日志级别：
- `DEBUG`：详细的诊断信息
- `INFO`：一般信息性消息（默认）
- `WARNING`：潜在问题的警告消息
- `ERROR`：失败的错误消息
- `CRITICAL`：需要立即关注的严重错误

在 `config.yaml` 中配置日志级别：

```yaml
service:
  log_level: "info"  # debug, info, warning, error, critical
```

或通过环境变量：
```bash
export LOG_LEVEL=debug
```

### 日志格式

所有日志遵循结构化格式：

```
YYYY-MM-DD HH:MM:SS - [request_id] - module_name - LEVEL - [file:line] - message | extra_fields
```

示例：
```
2025-11-11 10:30:45 - [abc123] - main - INFO - [main.py:234] - 规划成功完成：52 个航点，planning_time=45.30ms，total_time=52.70ms | success=True, num_waypoints=52, algorithm=kinodynamic
```

### 请求关联

每个请求都分配一个唯一的请求 ID（8 字符 UUID），出现在所有相关日志条目中。这使得能够在整个系统中跟踪请求。

请求 ID 也在响应头中返回：
- `X-Request-ID`：唯一请求标识符
- `X-Process-Time-MS`：总处理时间（毫秒）

## 请求/响应日志

### 传入请求

每个传入请求都记录：
- 请求 ID
- HTTP 方法和路径
- 客户端 IP 地址
- 查询参数

示例：
```
2025-11-11 10:30:45 - [abc123] - main - INFO - 传入请求：POST /plan | method=POST, path=/plan, client=192.168.1.100
```

### 响应

每个响应都记录：
- 请求 ID
- HTTP 状态代码
- 处理时间（毫秒）

示例：
```
2025-11-11 10:30:45 - [abc123] - main - INFO - 响应：200（耗时 52.70ms）| status_code=200, process_time_ms=52.70
```

## 规划性能日志

### 规划请求

每个规划请求记录：
- 起点和目标位置
- 规划参数（速度、加速度、算法）
- 是否使用当前里程计

示例：
```
2025-11-11 10:30:45 - [abc123] - main - INFO - 收到规划请求 | start={'x': 0.0, 'y': 0.0, 'z': 1.0}, goal={'x': 10.0, 'y': 5.0, 'z': 1.5}, algorithm=kinodynamic
```

### 规划结果

成功的规划日志包括：
- 航点数量
- 轨迹持续时间
- 规划时间（ROS 和总计）
- 成功率

示例：
```
2025-11-11 10:30:45 - [abc123] - planning_client - INFO - 规划成功：52 个航点，持续时间=5.20s，planning_time=45.3ms，total_time=52.7ms | num_waypoints=52, trajectory_duration=5.2, planning_time_ms=45.3, ros_planning_time_ms=38.1, total_time_ms=52.7, success_rate=0.95
```

## 错误日志

### 错误类别

所有错误都以适当的严重性记录：

1. **验证错误（400）**：记录为 WARNING
   - 无效的请求参数
   - 超出边界的位置
   - 无效的算法选择

2. **规划失败（422）**：记录为 WARNING
   - 未找到路径
   - 起点/目标碰撞
   - 轨迹优化失败

3. **服务错误（503）**：记录为 ERROR
   - ROS 连接丢失
   - 里程计不可用
   - Fast-Planner 无响应

4. **超时错误（504）**：记录为 WARNING
   - 超过规划超时

5. **内部错误（500）**：记录为 ERROR，带堆栈跟踪

### 堆栈跟踪

内部错误和意外异常包括完整的堆栈跟踪：

```
2025-11-11 10:30:45 - [abc123] - main - ERROR - /plan 上的意外错误：ValueError: 无效轨迹 | error_code=internal_error, exception_type=ValueError
Traceback (most recent call last):
  File "main.py", line 234, in plan_trajectory
    ...
ValueError: 无效轨迹
```

## 性能指标

### 指标端点

`/metrics` 端点提供实时性能统计：

```bash
curl http://localhost:8000/metrics
```

响应：
```json
{
  "uptime_seconds": 3600.5,
  "total_requests": 150,
  "successful_requests": 142,
  "failed_requests": 8,
  "success_rate_percent": 94.67,
  "last_planning_success": 1699876543.123,
  "ros_connected": true
}
```

### 性能记录器

`PerformanceLogger` 类提供记录指标的便捷方法：

```python
from fastapi_planner.logging_config import PerformanceLogger, get_logger

logger = get_logger(__name__)
perf_logger = PerformanceLogger(logger)

# 记录时间
perf_logger.log_timing("planning", 45.3, success=True, algorithm="kinodynamic")

# 记录比率
perf_logger.log_rate("success_rate", 95, 100)

# 记录计数器
perf_logger.log_counter("request_count", 42)
```

## 健康监控

### 健康端点

`/health` 端点提供服务健康状态：

```bash
curl http://localhost:8000/health
```

响应：
```json
{
  "status": "healthy",
  "ros_connected": true,
  "fast_planner_available": true,
  "uptime_seconds": 3600.5,
  "last_planning_success": 1699876543.123,
  "odometry_age_ms": 50.2
}
```

健康状态值：
- `healthy`：ROS 已连接且 Fast-Planner 可用
- `degraded`：ROS 已连接但 Fast-Planner 无响应
- `unhealthy`：ROS 连接丢失

## 监控最佳实践

### 日志分析

使用结构化日志字段进行过滤和分析：

```bash
# 按请求 ID 过滤
grep "abc123" service.log

# 按错误代码过滤
grep "error_code=no_path_found" service.log

# 按规划时间过滤
grep "planning_time_ms" service.log | grep -E "planning_time_ms=[0-9]{3,}"
```

### 性能监控

监控这些关键指标：
- **成功率**：正常运行时应 > 90%
- **规划时间**：大多数请求应 < 100ms
- **里程计年龄**：四旋翼活动时应 < 100ms
- **正常运行时间**：跟踪服务重启

### 告警

为以下情况设置告警：
- 成功率降至 80% 以下
- 规划时间持续超过 500ms
- ROS 连接丢失（状态 = unhealthy）
- 高错误率（> 10% 的请求）

## 日志轮转

对于生产部署，配置日志轮转以防止磁盘空间问题：

```bash
# 使用 logrotate
/var/log/fastapi-planner/*.log {
    daily
    rotate 7
    compress
    delaycompress
    missingok
    notifempty
    create 0644 app app
}
```

## 与监控工具集成

### Prometheus

使用自定义导出器通过 `/metrics` 端点将指标导出到 Prometheus。

### ELK Stack

将日志发送到 Elasticsearch 进行集中日志记录和分析：

```bash
# 使用 Filebeat
filebeat.inputs:
- type: log
  enabled: true
  paths:
    - /var/log/fastapi-planner/*.log
  json.keys_under_root: true
  json.add_error_key: true
```

### Grafana

创建仪表板以可视化：
- 随时间变化的请求率
- 成功率趋势
- 规划时间分布
- 按类型的错误率

## 故障排除

### 高规划时间

检查日志：
```bash
grep "planning_time_ms" service.log | awk '{print $NF}' | sort -n | tail -20
```

### 频繁失败

分析错误代码：
```bash
grep "error_code" service.log | cut -d'=' -f2 | cut -d',' -f1 | sort | uniq -c | sort -rn
```

### ROS 连接问题

监控 ROS 连接状态：
```bash
grep "ros_connected" service.log | tail -20
```
